# 雲端資料庫設定

目前網站仍使用瀏覽器資料，尚未切換雲端。這個目錄先準備資料庫與權限，不會上傳或刪除現有設備。

## 1. 備份

在目前有正式資料的瀏覽器，使用系統「備份與還原」匯出完整備份，保留原檔。

## 2. 建立資料表

在 Supabase 專案左側開啟 SQL Editor → New query，貼上 `migrations/202610290001_cloud_workspace.sql` 的完整內容後按 Run。

腳本建立工作區、成員與共用資料，以及讀寫 API。新建的工作區不包含任何使用者權限，匿名訪客不可讀寫；必須先授權應用程式帳號。腳本不需要修改自動公開資料表的設定。

初期採一份完整共用資料文件，保存目前欄位、進度與關聯識別碼，減少移轉遺漏。每次寫入比對版本，發生多人同時編輯時拒絕舊版本覆蓋。網站仍需實作衝突提示、重新載入與未儲存修改保留；伺服器拒絕衝突不等於已完成自動合併。

## 3. 建立第一個系統帳號

Authentication → Users → Add user 建立 Email/Password 使用者。這是設備網站的登入帳號，與登入 Supabase 管理後台的 GitHub 帳號分開。密碼不必提供給開發者。

將 `add-first-admin.sql` 裡的 `REPLACE_WITH_YOUR_EMAIL` 換成剛才的帳號 Email，在 SQL Editor 執行，授予該帳號管理員身分。其他使用者即使自行註冊，也不會取得設備資料存取權。正式使用時建議在 Authentication 設定關閉公開註冊，由管理員建立帳號。

## 4. 下一階段

確認 SQL 成功後，接續製作登入、雲端讀寫與首次移轉介面，再核對各月份資料。首次移轉必須由使用者選擇正確的本機備份/資料來源，不得自動把 DEMO 範例覆蓋到正式雲端。

年度 Excel 封存、容量監控與雲端排程尚未製作。

`public-config.json` 只包含可公開的 Project URL 與 Publishable Key；不得加入資料庫密碼、Secret Key 或 service_role Key。
