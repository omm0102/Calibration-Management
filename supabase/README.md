# 雲端資料庫設定

網站已加入 Email/Password 登入與雲端同步。原始瀏覽器資料會保留；第一次上傳必須由使用者確認資料來源，不會自動上傳 DEMO。資料庫尚無資料時，登入者會看到首次移轉介面。

## 1. 備份

在目前有正式資料的瀏覽器，使用系統「備份與還原」匯出完整備份，保留原檔。

## 2. 建立資料表

在 Supabase 專案左側開啟 SQL Editor → New query，貼上 `migrations/202610290001_cloud_workspace.sql` 的完整內容後按 Run。

腳本建立工作區、成員與共用資料，以及讀寫 API。新建的工作區不包含任何使用者權限，匿名訪客不可讀寫；必須先授權應用程式帳號。腳本不需要修改自動公開資料表的設定。

初期採一份完整共用資料文件，保存目前欄位、進度與關聯識別碼，減少移轉遺漏。每次寫入比對版本，發生多人同時編輯時拒絕舊版本覆蓋。網站已加入衝突提示、重新載入與 IndexedDB 未儲存修改保留；不會自動合併衝突。請先下載未同步備份，再明確確認載入最新資料。

## 3. 建立第一個系統帳號

Authentication → Users → Add user 建立 Email/Password 使用者。這是設備網站的登入帳號，與登入 Supabase 管理後台的 GitHub 帳號分開。密碼不必提供給開發者。

將 `add-first-admin.sql` 裡的 `REPLACE_WITH_YOUR_EMAIL` 換成剛才的帳號 Email，在 SQL Editor 執行，授予該帳號管理員身分。其他使用者即使自行註冊，也不會取得設備資料存取權。正式使用時建議在 Authentication 設定關閉公開註冊，由管理員建立帳號。

## 4. 登入及首次移轉

使用部署後的網站，以 Authentication 建立的 Email/Password 登入。

- 雲端沒有資料：先下載本機完整備份，核對月份與設備數，勾選確認後移轉；也可以選擇先前匯出的完整備份。兩種方式都不會自動將 DEMO 上傳。
- 雲端已有資料：讀取共用資料，保留原始本機資料，不會把其他電腦的 DEMO 覆蓋到雲端。
- 每次修改約 650 ms 後合併儲存。帳號、雲端操作與登出集中於左側圖標列底部的帳號選單；儲存失敗或衝突時圖標出現紅點，展開可查看並處理。正常儲存不顯示成功文字，讀取時保留動畫。
- 登入時讀取雲端；持續開著的分頁在台灣日期換日後，第一次切回網頁或每分鐘檢查時會讀取一次。每日成功後不再重複下載，沒有即時推播或自動合併。
- 雲端讀取成功後預設進入儀表板，卡片依序由下往上滑出，月份與篩選偏好保留；未儲存修改、儲存中、開啟彈窗、輸入欄位焦點或月報編輯頁會延後更新，稍後再檢查。連線失敗不清空畫面，五分鐘後重試；恢復網路可立即重試。手動「重新整理雲端」仍可隨時使用。
- 斷線修改保留於本機 IndexedDB，登入憑證只保存在該分頁的 sessionStorage。不要在尚未同步前清除網站資料或使用會自動清除儲存的無痕模式。
- 月份篩選與欄位顯示偏好保留在各瀏覽器/使用者，不會覆蓋其他使用者的設定。
- 月報草稿按雲端使用者隔離，已同步的月報以雲端紀錄為準。
- 清冊廠商欄位使用依廠商資訊表格排序的完整下拉選單（不受搜尋條件影響），最後為「其他」；新輸入廠商會加入資訊清單。設備以 vendorInfoId 連結廠商，改名時同步關聯設備名稱但保留進度。
- 外校表格的寄出／收件選擇放在日期表頭，切換僅改變檢視、不清除設備資料。編輯日期時分別保存 shippedDate 與 receiptDate，避免切換造成日期遺失。日期與文字置中，外校與遊校表格列均為白色。
- 外校／遊校以 calibrationDate 代替「已完成」操作，填入校驗日期即為完成，清除即取消。舊完成紀錄會帶入原 completed 日期。已移除所有廠商整批控制；清冊顯示廠商校驗時間。receiptDate 保存外校收件日期，寄出日期不會拿來計算週期。廠商平均校驗週期以所有月份外校設備的有效「校驗日期－收件日期」平均計算，缺日期或負天數不納入；尚無資料時保留手填天數。有自動平均值時編輯框天數為唯讀，可修改或清除設備日期來更新。
- 廠商可保存名稱下方副標註 vendorNote、一般備註 notes 及多位 contacts（name/method/email 三格成組），並保留舊 contact/contactMethod/email 作第一位聯絡人的相容欄位。週期可點擊查看依校驗日期年月分組的設備明細，缺收件日期或日期順序錯誤顯示「—」且不納入平均；只有手動週期時不會產生虛構設備紀錄。
- 外校廠商資訊存於共用資料的 externalVendors，跨月份共用，包含名稱、平均校驗天數、聯絡人、聯絡方式與 E-mail。舊資料沒有這個欄位時視為空清單，不需要額外執行 SQL；新增後會跟隨雲端同步及完整備份。
- 完整備份只包含系統資料與月報儲存，不會包含登入 token。
- 「從備份還原」在登入後會顯示取代共用資料的確認，不會清除登入憑證。

年度 Excel 封存、容量監控與雲端排程尚未製作。

`public-config.json` 與 `dist/cloud.js` 只包含可公開的 Project URL 與 Publishable Key；不得加入資料庫密碼、Secret Key 或 service_role Key。

## 5. 驗證

`tests/cloud-sync.cjs` 使用 Playwright 攔截 Supabase 請求，涵蓋登入錯誤、首次移轉確認、原始資料保留、月報移轉、偏好排除、儲存、斷線重試、版本衝突與備份不含憑證。使用本機靜態伺服器供應 dist，再執行：

```sh
APP_TEST_URL=http://127.0.0.1:8008 node tests/cloud-sync.cjs
APP_TEST_URL=http://127.0.0.1:8008 node tests/cloud-daily-sync.cjs
APP_TEST_URL=http://127.0.0.1:8008 node tests/vendor-info.cjs
APP_TEST_URL=http://127.0.0.1:8008 node tests/vendor-details-history.cjs
```

`cloud-daily-sync.cjs` 另驗證台灣日期標記、每日去重、成功讀取進入儀表板、編輯延後、過期回應不覆蓋與失敗重試。

需要安裝 Playwright，或以 `PLAYWRIGHT_MODULE` 指定可用模組路徑。模擬測試不等於正式專案登入驗證；正式登入應由帳號持有人在瀏覽器操作，無需提供密碼。
